# Upstream review for OneCLI v2.20.0

Reviewed upstream from `8ea47cd8` through `90e874c0` (tag `v2.20.0`) against fork `origin/v2` at `e575b8a2`. The fork's default `main` is still on the v1.45 line. The [migration plan](../v2-migration/plan.md) puts v2 work on `v2` and schedules the `main` cutover after the Phase 6 gate.

The 32 upstream commits change 2,859 files, including 125 deletions. The fork and upstream both changed 249 paths relative to the prior review anchor. An in-memory three-way merge trial reported 185 conflicted paths, including 82 outside the three fork-owned enterprise replacement roots. Upstream changed 211 paths across those roots. Applying automatic merge results there would import upstream changes even on paths without a Git conflict.

The API's new edition defaults call enterprise attachment storage, Slack-as-user and hosted desktop modules that the fork lacks. Retain the on-prem attachment store and disabled hosted capability slots. The new web settings modal also imports enterprise settings components. Route it to fork-owned settings and keep registration and org-admin checks in the resulting flow. The gateway's new granular-access call sites expect an async guard for Drive folder resolution. Adapt them to the existing fork guard before taking Drive-specific behavior.

Start adoption on the isolated branch from `origin/v2`. Stage and validate gateway, API/database, web and deployment changes before any cutover. Run Rust and TypeScript checks, then exercise registration, org and workspace access, both proxy entry points, scoped credentials, budgets, certificate binding and Nanoclaw onboarding. Keep new transports disabled until there is an explicit decision to take them.
