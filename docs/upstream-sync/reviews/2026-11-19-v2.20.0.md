An in-memory three-way merge trial reported 185 conflicted paths, including 82 outside the three fork-owned enterprise replacement roots. Upstream changed 211 paths across those roots. Applying automatic merge results there would import upstream changes even on paths without a Git conflict.

## Integration on the v2 branch

The integration branch merges upstream commit `90e874c0` into the fork's v2 history. The gateway uses the fork's credential and policy checks. Raw browser tunnels and native PostgreSQL connections remain deferred until those transports can enforce the fork's policies. The sandbox supervisor uses the free desktop startup path. The upstream release adds a fourth enterprise directory under that supervisor, which the fork excludes along with upstream's other enterprise implementations.

The fork builds four service images and uses upstream images for the runtime services. Its Helm chart runs from the checkout. The API and dashboard share the registration setting, and the gateway uses one replica for its in-memory stores.

A PostgreSQL 16 rehearsal applied the existing fork migrations and then all 58 new migrations. The resulting database matched the Prisma schema. A second upgrade preserved a seeded API key's last-used timestamp and its workspace's client-host binding, and transferred a workspace skill to the hosted agent. The full repository script suite passed with Helm available, including chart rendering. All five chart values fixtures passed strict lint.
