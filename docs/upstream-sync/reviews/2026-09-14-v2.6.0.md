# Upstream review — v1.45.0 → v2.6.0 (2026-09-14)

Range: `84ccaf7` (v1.45.0) → `8ea47cd` (v2.6.0 + 2). 36 commits, 12 releases, 2190 files, +314k / −24k lines outside docs.
Fork tip reviewed against: `integration/wave2-plus-followups` @ `6e2c3b4` (PR #51), plus open PR branches #1, #2–#5, #7, #52.

This is not an incremental cycle. v2.0.0 (PR onecli/onecli#497, 2026-08-17) is a single cutover commit that changes the product, the topology, the auth stack, and the licensing model. The question this review answers is not "which commits to take" but **"is v2 a viable base for this fork at all"**.

## What v2 is

- **Product:** "the agent harness built for teams". Hosted agents run in sandboxes (jcode harness, not Claude Code) managed by a `runner`, with chat, memory, schedules, Slack, and SSH. The credential gateway is now one component of that, and BYO agents (our nanoclaw use case) are the legacy lane: `Agent.kind` defaults to `"byo"`, but the create-agent UI hides the BYO door once a runner is registered, and onboarding is chat-first.
- **Topology:** the all-in-one image is gone. Minimal stack is `postgres` + one-shot `migrations` + `api` (Hono, :10256) + `web` (:10254) + `gateway` (:10255). `runner`, `ssh-terminator`, `channel-adapter` are profile-gated and can be left off. No Redis on self-host. `/v1` no longer exists on the web container in production.
- **Auth:** better-auth on the api-server. Email/password registration is always on and **has no off switch by design**; Google is an optional extra provider. `AUTH_MODE=local` and `NEXTAUTH_SECRET` are gone. A pre-2.0 install's data is handed to the _first account that registers_ after upgrade.
- **Tenancy:** `Project` → `Workspace` renamed in place (ids preserved, `X-Project-Id` accepted with a deprecation header for a window). Org → Workspace → resources, with org-scoped twins for secrets/connections/app config/policy/API keys.
- **Licensing:** `apps/web/src/ee/`, `packages/api/src/ee/`, `apps/gateway/crates/ee/` are under LICENSE-ENTERPRISE (production use requires a subscription). The gate is `ENTERPRISE_ENABLED=true`, an honor-system env var. **The licensed code is compiled into every build** and only degraded at runtime: the four free gateway crates hard-depend on the `ee` crate, the free `routes/workspaces.ts` imports `ee/services/workspace-service.ts`, and `packages/api/src/licensing/ee-boundary.ts` pins 47 such crossings as declared debt.

## What v2 puts behind the enterprise license

`ENTERPRISE_FEATURES` in `packages/api/src/lib/entitlements.ts`: `rbac`, `groups`, `granular_access`, `workspace_sharing`, `multi_org`, `budget`, `sso` (incl. domains + SCIM), `app_availability`, `provisioning`, `members_directory`, `ha`.

Unlicensed self-host is explicitly a "flat team": every active member passes every admin gate (`CAPS.rbac = false`), role changes 403, groups/domains/workspace-access routers 403, resource scopes are never stamped so **scoped grants inject the broad token unscoped** (the v1.45 `has_request_guard` accident, now the documented posture at `crates/proxy/src/connect.rs:181-196`), and budgets are dormant even when licensed.

That list is, almost item for item, the fork's reason to exist.

Where **v2 is ahead** of the fork and worth taking regardless of the base decision:

- 407 on untokened CONNECT/absolute-form (the fork tunnels untokened requests as an open relay). `crates/server/src/lib.rs:852-864`.
- Any `oc_` bearer commits to key auth; invalid keys no longer fall through to session auth. `crates/context/src/auth.rs`.
- Approval lookup collapses NotFound/WrongWorkspace into one 404 (closes an existence oracle).
- Credentialed CORS restricted to trusted origins (#520); bounded upstream response-header wait + suspect pool rotation (#541); OpenAI host expansion limited to OAuth secrets (#525); API status preserved for malformed error bodies (#559).
- better-auth with Google, password reset, CLI device auth.
- `gateway-e2e` black-box suite.

## Migration and compatibility facts

- Schema chain is continuous: fork has 86 migrations, upstream 125, shared through `20260727035117_drop_agent_groups`. A 1.45 database walks forward in place. The fork's two extra migrations (`invitations.project_id`, `api_keys.last_used_at`) interleave by timestamp and would need re-homing.
- `20260802070214_drop_legacy_policy_model` drops `policy_rules`, `agent_secrets`, `agent_app_connections`; `20260803215518_remove_partner_layer` drops the partner tables; `20260810170000_rename_project_to_workspace` takes ACCESS EXCLUSIVE locks and is "NOT safe inside a rolling deploy".
- nanoclaw: the proxy hop is unchanged (`http://x:aoc_...@gateway:10255`, same MITM CA). The control-plane hop breaks: `ONECLI_URL=http://host:10254` must become the api-server origin (:10256 or a path-routed `/v1`). `GET /v1/container-config` without `agent=` returns 404 on a fresh v2 workspace. `POST /v1/agents` and `GET /v1/gateway/ca` still exist.
- Publishing: 8-image GHCR matrix, every workflow job guarded by `github.repository == 'onecli/onecli'`, drift-guard tests in `scripts/` assert the matrix and the literal guard, `install.sh` and compose hard-code `ghcr.io/onecli/*` and `onecli.sh`.
- `pnpm check` now runs licensing suites that snapshot the ee file/symbol lists, pin `CROSSING_DEBT = 47`, and require every ee mount to refuse unlicensed. Any fork change that moves code across the ee line or flips the gate fails them (they can be re-snapshotted, but that is a permanent tax).

## Open decisions for a human

1. **Base line.** Stay on the 1.45-based fork and cherry-pick the security fixes (items 2–9), or rebase onto v2 and re-land roughly 20k source lines of fork work plus the unmerged 7.6k-line relay stack. The rebase does not remove the need for the fork's own implementations: everything the fork built for team use (RBAC enforcement, groups, workspace access, domains, budgets, request-layer scoping) is licensed upstream, so on v2 the fork would carry Apache re-implementations _alongside_ the shipped ee code, against boundary tests designed to stop exactly that.
2. **License posture for Graphite.** If a hosted offering ships from this fork, it cannot run upstream's ee paths in production without a subscription, and the "OSS" v2 binary contains them. A v2-based Graphite needs either an `ee-shim` crate plus web/api re-homing (3–5 days gateway, more for web/api, and a permanent snapshot-fight in CI), or a subscription. A 1.45-based Graphite has no ee code in-tree at all.
3. **Auth model.** v2 forces open email/password registration with no switch. For a small team behind Google login this is a regression that would need a fork patch either way.
4. **BYO agents as first-class.** Upstream's direction is hosted-agents-first; the BYO create door already disappears once a runner exists. Staying close to upstream means absorbing that drift every release.

## Recommendation

Do not rebase onto v2 now. Treat v2 as a **source to cherry-pick from**, not a base:

- Land #51 and #52, then a small hardening PR with items 2–8 (all gateway or API, all under two days total).
- Retarget the relay stack (#2–#5) onto main; it has no upstream competitor and Graphite's remote-gateway story depends on it.
- Revisit the base decision if upstream (a) moves the tenancy services out of `ee/` as their debt note promises, (b) ships a registration switch, or (c) the team decides to pay for enterprise.

The cost of staying is real but bounded: we forgo the api-server split, better-auth, and the e2e harness, and future upstream fixes will need hand-porting across a widening gap. The cost of moving is a multi-month re-land that ends with the fork still maintaining its own copies of every feature it cares about.

## Decision (2026-09-14, Marco)

**Build on v2.** Replace the three enterprise-licensed directories with the fork's own clean-room implementations, written against the seams the free code already calls (provider init functions, `ee::` module paths, route mounts), and trimmed to the fork's use case rather than feature-complete. The recommendation above to stay on 1.45 is superseded. Rationale: staying froze the fork on an abandoned line and forfeited the api-server split, better-auth, the e2e harness and every future upstream fix; the licensing problem is solved by not shipping upstream's `ee/` at all.
